```
┌──────────────────────────────────────────────────────────────┐
│                    ChatService                              │
│                                                              │
│  ┌─────────────┐        ┌──────────────┐                   │
│  │   REST API  │───────▶│ MessageQueue │◀──────┐           │
│  │             │        │              │       │           │
│  │ POST /msg   │        │ - Redis/     │       │           │
│  │ GET /msg    │        │   Memory     │       │           │
│  └─────────────┘        └──────────────┘       │           │
│                                  │             │           │
│                                  ▼             │           │
│  ┌─────────────────────────────────────┐      │           │
│  │      ConnectionManager              │──────┘           │
│  │  ┌─────────────────────────────┐    │                 │
│  │  │ user_id: [ws1, ws2, ...]    │    │                 │
│  │  └─────────────────────────────┘    │                 │
│  └─────────────────────────────────────┘                 │
│           │                  │                             │
│           ▼                  ▼                             │
│  ┌─────────────┐    ┌─────────────┐                       │
│  │  WebSocket  │    │  WebSocket  │                       │
│  │  Client A   │    │  Client B   │                       │
│  └─────────────┘    └─────────────┘                       │
└──────────────────────────────────────────────────────────────┘

Сценарий кросс-доставки:
┌─────────────────┐       ┌─────────────────┐
│ Service A       │       │ Service B       │
│ (REST client)   │       │ (WebSocket)     │
└────────┬────────┘       └────────┬────────┘
         │                          │
         │ POST /messages           │ on_message()
         │                          │
         └──────────┬───────────────┘
                    ▼
         ┌──────────────────┐
         │ Message сохранено│
         │ в БД             │
         └────────┬─────────┘
                  │
         ┌────────▼─────────┐
         │ Уведомление в    │
         │ ConnectionManager│
         └────────┬─────────┘
                  │
         ┌────────▼─────────┐
         │ WebSocket push   │
         │ к Service B      │
         └──────────────────┘
```

## Стандартные поля для идентификации

### Базовый набор для всех запросов
```json
{
  "user_id": "UUID",           // Уникальный ID пользователя
  "service_id": "str",         // Идентификатор сервиса-клиента
  "auth_token": "str"          // JWT токен
}
```

### Для регистрации
```json
{
  "email": "str",
  "service_id": "str",
  "public_key": "str"          // RSA/ECDSA публичный ключ
}
```

### Для сообщений
```json
{
  "sender_id": "UUID",
  "recipient_id": "UUID",
  "encrypted_data": "str",     // Base64 зашифрованных данных
  "encryption_key": "str",     // Зашифрованный ключ AES
  "signature": "str"           // Цифровая подпись
}
```

## API Endpoints

### REST API
```
POST   /api/v1/messages              # Отправить (доставит по WebSocket)
GET    /api/v1/messages              # Получить (для REST клиентов)
GET    /api/v1/messages/{id}         # Конкретное сообщение
GET    /api/v1/messages/unread       # Непрочитанные

### WebSocket
WS     /ws/{user_id}?token={jwt}     # Real-time соединение

### Auth & Keys
POST   /api/v1/auth/register         # Регистрация с ключами
POST   /api/v1/auth/login            # Получение JWT
GET    /api/v1/keys/public/{user_id} # Получить публичный ключ
```

## Вариант 2: Hybrid Encryption

Концепция: Симметричное шифрование сообщений + асимметричное для обмена ключами

### Преимущества
- Баланс безопасности и производительности
- Гибкость в настройке прав доступа
- Подходит для множества сервисов
- End-to-End encryption с возможностью восстановления

### Технические детали
- **AES-256-GCM** для шифрования сообщений
- **RSA-4096** или **ECDSA** для обмена ключами
- **JWT** для авторизации
- **API Keys** для сервисов
